# 安装包资产模板（基线）

> **这是安装包内个人资产类文件的唯一来源。**
> 打包时从本目录生成 `packages/desktop/resources/seed/`，**不要反过来从作者的真实资产删改**。

## 为什么有这个目录

过去每次出包，都是从作者正在用的 `AGENTS.md` / `SE-AGENTS.md` / 经验库里
「挑一遍、删一遍」再塞进安装包。这套做法的三个问题：

1. **每次都要重新判断**哪些内容算个人内容，判断标准不稳定，容易漏。
2. **漏一次就等于把作者的东西发出去**。已经发生过：真实的图片素材名、
   真实代理端口、众测项目编号、事故经历被带进过 5 个版本的安装包。
3. **改动不可追溯**。作者的真实资产持续演进，安装包里的那份到底是哪一版，
   没人说得清。

改成「基线目录 → 生成 seed」之后：基线是**独立的、被审阅过的**一份文件，
出包只是复制；作者的真实资产再怎么演进，也不会流进安装包。

## 目录结构

```
templates/installer-assets/
├─ README.md                  # 本文件
├─ prefs/
│  ├─ AGENTS.md               # 基础偏好模板（占位符，无个人内容）
│  ├─ SE-AGENTS.md            # 额外偏好模板（空白骨架）
│  └─ WARMUP.md               # 启动预热模板（当前任务：暂无）
└─ ex-bags/
   ├─ _TAXONOMY.md            # 标签词表（通用，可随产品演进）
   ├─ _INDEX.md               # 索引空骨架
   ├─ _state/TASK_STATE.md    # 交接文件空骨架
   └─ <10 个域目录>/.gitkeep  # 只保留目录结构
```

## 三类资产的定位（务必区分）

| 资产 | 在安装包里的形态 | 用户装完后 |
|---|---|---|
| **经验树** `ex-bags/` | 只有词表、空索引、空交接、10 个空目录 | 用户自己积累 |
| **额外偏好** `SE-AGENTS.md` | 空白骨架 + 占位符示例 | **按需自行创建**，安装包不预置到用户目录 |
| **偏好池** `instruction_entry` 表 | **不在安装包里**（存在数据库里） | 全新安装为空 |

## 升级基线时的正确做法

### 要改通用规则（产品行为、经验库用法等）

直接编辑 `templates/installer-assets/prefs/AGENTS.md`，然后：

```powershell
# 基线 -> seed，单向复制
robocopy templates\installer-assets packages\desktop\resources\seed /MIR /NFL /NDL /NJH /NJS /nc /ns /np
```

**不要**从 `C:\Users\Administrator\AGENTS.md` 反向同步过来。

### 作者的真实资产有新规则想带进安装包

判断标准：**换个用户装完，这条规则还成立吗？**

- 成立（例如「文件默认输出到工作区目录」）→ 提炼成通用表述，写进基线
- 不成立（例如「雷神众测 11655 号项目要附截图」）→ **留在作者自己的经验库里，不进基线**

### 新写一篇经验文档后

**不需要**同步进安装包。安装包只提供空骨架，经验正文永远不进分发物。

## 出包前的校验

`script/asset-gate.ps1` 会强制检查，不合格直接中止打包。规则：

1. **经验树**：只允许 `_INDEX.md`、`_TAXONOMY.md`、`_state/TASK_STATE.md`、`.gitkeep`。
   **出现任何其他文件即失败**（那意味着真实经验条目被带进包了）。
2. **额外偏好**：`SE-AGENTS.md` 必须小于 8 KB。作者的真实那份约 58 KB，
   基线这份 1.5 KB，体积本身就是一道粗筛。
3. **机器标识字面量**：seed 下禁止出现作者的本机路径、内网地址、主机名、
   工具目录等。
4. **包内禁止数据库**：`wlstudio.db*` 出现即失败（偏好池只在库里，不落盘）。
5. **二进制也扫**：内核 exe 里的构建机路径逐个核对，只放行工具链固有项，
   出现新的路径就失败。

校验器自带反向测试（`gate-selftest.ps1`），会故意注入 4 种泄露并确认都被拦住，
避免校验退化成永远通过的摆设。

## 语义审阅（正则替代方案）

正则只能证明「没有命中已知关键词」，不能证明「内容该不该出现」。
所以每次出大版本前，还要**实际通读**下面这些文件：

```
templates/installer-assets/prefs/AGENTS.md
templates/installer-assets/prefs/SE-AGENTS.md
templates/installer-assets/prefs/WARMUP.md
templates/installer-assets/ex-bags/_INDEX.md
templates/installer-assets/ex-bags/_state/TASK_STATE.md
```

通读时判断的不是「有没有某个词」，而是：**这段内容换个用户读，会不会觉得是别人的私事？**

常见漏网内容（正则不易发现）：

- 具体业务项目的平台名、项目编号、漏洞序号
- 「某年某月血泪教训」这类事故标题，及事发经过
- 作者自己的分发/打包作业规范（用户不需要知道你怎么出包）
- 开发环境内部关系（例如 A 进程和 B 进程互相独立）
- 具体素材文件名、具体报告模板路径
